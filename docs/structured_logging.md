# Structured Logging

Origami API writes JSON operation events for critical Dashboard/API actions.
These logs are the staging and production trail for who triggered a run, which
request created it, where it came from, and which run artifact to inspect.

## Event Contract

Operation log records use:

- `event`: always `origami_api_operation`
- `action`: operation name, such as `run_scenario` or `scenario_create`
- `environment`: `ORIGAMI_ENV`
- `request_id`: supplied `X-Request-ID` or generated by the API
- `actor`: trusted proxy identity, token-authenticated, or anonymous
- `source_ip`: first `X-Forwarded-For` address or client IP
- `method` and `path`: HTTP request surface
- `status_code`: operation status
- `target`: scenario id or other operation target when available
- `run_id`: run history/artifact id for run operations
- `timestamp`: UTC ISO timestamp
- `metadata`: operation-specific structured details

The same `request_id` is returned in the `X-Request-ID` response header so a
browser/API failure can be matched to API logs.

## Staging Queries

Show recent API operation events:

```bash
docker compose --env-file .env.staging -f docker-compose.prod.yml -f docker-compose.sso.yml \
  logs --no-color --tail=300 api \
  | grep origami_api_operation
```

Validate the structured field contract:

```bash
docker compose --env-file .env.staging -f docker-compose.prod.yml -f docker-compose.sso.yml \
  logs --no-color --tail=300 api \
  | scripts/validate_structured_logs.py --require-run-id
```

Find one run from its `run_id`:

```bash
docker compose --env-file .env.staging -f docker-compose.prod.yml -f docker-compose.sso.yml \
  logs --no-color api \
  | grep origami_api_operation \
  | grep '<run-id>'
```

Find one failing browser/API request from its response header:

```bash
docker compose --env-file .env.staging -f docker-compose.prod.yml -f docker-compose.sso.yml \
  logs --no-color api \
  | grep '<x-request-id>'
```

## Acceptance

Before marking staging operational:

- Trigger a scenario run through Dashboard or API.
- Capture the `X-Request-ID` response header.
- Confirm API logs contain an `origami_api_operation` record with that
  `request_id`.
- Confirm the same log record has a non-empty `run_id`.
- Open Dashboard run history for that `run_id`.
- Run `scripts/validate_structured_logs.py --require-run-id` against recent API
  logs and keep the result in the staging rehearsal notes.

## Notes

Do not put secrets in `metadata`. The API logs operation facts and artifact
links, not raw API tokens, OAuth cookies, or user-provided private data.
